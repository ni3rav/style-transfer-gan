Ukiyo-e

Notes on the finished photo-to-print model, the charts in the training notebook, and how to run it.

This is a CycleGAN trained on the official unpaired ukiyoe2photo set. Domain A is Ukiyo-e prints. Domain B is landscape photos. Nothing in the training set is a before-and-after pair, so the model cannot copy a paired example.

The finished run is the 20-epoch checkpoint described in src/notebooks/trained_fin.ipynb.

The four networks

The model learns two translators and two critics.

  • G_A, about 11.378 million parameters, turns a photo into a Ukiyo-e image. This is the network used after training.
  • G_B, the same size, turns a Ukiyo-e image back into a photo.
  • D_A, about 2.765 million parameters, judges whether an image belongs to the Ukiyo-e set.
  • D_B, the same size, judges whether an image belongs to the photo set.

Each generator is a 9-block ResNet: reflect-pad, a 7×7 convolution, two stride-2 downsamplings, nine residual blocks, two transposed convolutions, and a tanh output. Each critic is a 70×70 PatchGAN with three layers. Normalization is instance norm without an affine scale, and dropout is off. Weights start from a normal distribution with standard deviation 0.02.

Direction BtoA swaps the loaded batches before the loss. In the saved test pictures, real_A is the photo, fake_B is the Ukiyo-e translation, and rec_A is the photo reconstructed from that translation.

One training step

One step draws a photo and a print independently. The batch size is 1.

  1. The photo goes through G_A and then G_B. The result should match the original photo.
  2. The print goes through G_B and then G_A. The result should match the original print.
  3. G_A is also shown a real print and asked to leave it alone. G_B is shown a real photo and asked to leave it alone. That identity term keeps the generator from repainting color when the input is already in the target style.
  4. D_A tries to accept real prints and reject generated prints. D_B does the same for photos. The generators try to make the critics accept their fakes.
  5. The critic is not trained only on the latest fake. A replay buffer of 50 images sometimes substitutes an older fake, so the critic does not forget earlier generator mistakes.

The adversarial term is least-squares GAN loss: mean squared error against 1 for a real target and 0 for a fake target. The cycle and identity terms are L1. Cycle loss is multiplied by 10. Identity loss is that cycle term multiplied by 0.5, so its logged weight is 5.

There is no paired reconstruction loss against a ground-truth print of the same scene. A close reconstructed photo means the two generators kept the content. It does not by itself mean the print looks like a woodblock.

After training, inference uses G_A only.

The paper's usual schedule is 200 epochs. This run is the 20-epoch schedule above.

What each loss is pushing on

  • The GAN loss is the style pressure. It asks the translation to look like the other collection.
  • Cycle loss is the content anchor. It asks a round trip to come back to the same picture.
  • Identity loss is the color anchor. It asks a generator to leave an image alone when that image is already in the target style.

Instance norm, a PatchGAN, least-squares loss, and the replay buffer are the CycleGAN defaults this training kept.

What was measured

Eight training losses, plus a visual check of eight test photos. No FID, LPIPS, SSIM, or classification accuracy was computed.

The training cell prints only the latest five lines, and those windows overlap. Use the chart for the history.

The names follow the code after the BtoA swap:

  • D_A and G_A are the Ukiyo-e critic and the generator trying to fool it.
  • D_B and G_B are the photo critic and the generator trying to fool it.
  • cycle_A is photo → print → photo, already multiplied by 10.
  • cycle_B is print → photo → print, already multiplied by 10.
  • idt_A is G_A asked to leave a real print unchanged, already multiplied by 5.
  • idt_B is G_B asked to leave a real photo unchanged, already multiplied by 5.

How to read the eight graphs

Each panel is one loss. The horizontal axis is a log step, not an epoch. One point is written every 100 training iterations. An epoch of 6,287 images is about 63 points. Twenty epochs are about 1,257 points, which is why the axis runs to roughly 1,250. The first half of the axis is the constant learning rate. The second half is the decay.

The vertical scales are not the same. A cycle value near 1 and a discriminator value near 0.2 are not the same kind of number. The cycle and identity panels already include their weights.

The adversarial panels, D_A, G_A, D_B, and G_B, stay jagged for the whole run. D_A and D_B sit mostly between about 0.05 and 0.3, with spikes above 0.5. G_A and G_B sit mostly between about 0.2 and 1.0, with spikes near 1.75. They do not fall toward zero. For a least-squares GAN that is a balance: the critic keeps detecting some fakes, and the generator keeps fooling it on others. A spike is one difficult image, because the point is one batch of size 1.

The cycle and identity panels are the content curves. cycle_A starts near 8 and cycle_B near 4.5. Both fall within the first few epochs, about the first 200 log steps, and then sit in a noisy band around 1. idt_A starts near 2 and idt_B near 2.5, fall on the same early schedule, and then stay mostly below 1. idt_B has one sharp spike near 4 later in training. The early drop means the round trip started preserving the input. The later flat band means that part of training had settled. The line does not become smooth at the end, because each point is still one image.

The eight test rows

The last figure shows eight test photos. Each row is the photo, the G_A translation, and the reconstructed photo.

The reconstructions generally keep the scene. That matches the cycle loss settling near 1. The middle column is uneven. Some rows, such as the canal and the duck, read as painted. Others look closer to a grain laid over the photograph. The last landscape loses the hills. That is the quality this 20-epoch checkpoint reached. The figure is a sample of eight images, not a score over the whole test set.

Points worth saying

  • The training signal for style is unpaired. The cycle forces content to survive a round trip. The critic forces the output onto the look of the other set.
  • Identity loss is a color anchor. Cycle loss is a content anchor. The GAN loss is the style pressure.
  • The displayed adversarial losses are supposed to look noisy. The cycle and identity losses are the ones that should fall and then level off.
  • After epoch 20 the learning rate is zero and latest.pt is the finished checkpoint.

Train

Training does not run on this machine. Upload src/notebooks/ukiyoe_cyclegan.ipynb to Colab, set the runtime to a T4 GPU, and run the cells from the top.

The schedule is 20 epochs: 10 at learning rate 0.0002, then 10 of linear decay. One free session will not finish that. If the session drops, start a new one and run the cells from the top again. Training continues from MyDrive/ukiyoe-cyclegan/checkpoints/ukiyoe2photo/latest.pt. A file saved at the end of an epoch resumes at the next epoch. A file saved partway through resumes the rest of that epoch.

The finished run is already stored. src/notebooks/trained_fin.ipynb shows epoch 20 ending with the learning rate at 0. Running the training notebook again on that checkpoint does not train further.

During training, every 100 iterations the cell prints the last five stat lines and overwrites checkpoints/ukiyoe2photo/loss_plot.png with the full loss history.

Translate a photo locally

The local app loads G_A from src/server/ukiyoe_cyclegan.pt. That file is the finished checkpoint and is not committed.

From the repo root:

./start

The script installs the Python and npm dependencies, builds the page, and serves it at http://127.0.0.1:8000.

On the page, choose one photo. The browser stretches it to 256×256 and uploads that PNG. The page shows the 256×256 picture beside the Ukiyo-e result. A 256×256 pass on this machine's CPU can take about half a minute. A second request waits for the first. An upload that is not 256×256 is rejected. The server does not resize.

Stop the server with Ctrl+C in the terminal that ran ./start.
