Ukiyo-e

A walkthrough of the photo-to-print model, the charts from the finished run, and the page that runs it.

A landscape photo goes in. What comes out is meant to be the same place, drawn in the manner of a Japanese woodblock print: heavier outlines, flatter color, the grain and palette of the prints in the training set. That print style is the Ukiyo-e side of this project.

You already know a generator and a discriminator. The rest of this note is about why this particular model needs two of each, what one training step is asking them to do, and how the names in the notebook line up with those jobs.

The finished run is the 20-epoch checkpoint recorded in src/notebooks/trained_fin.ipynb. The numbers below were read from that notebook.

Two collections, and no matched pairs

A normal image-to-image network wants a correct answer for each input. You would show it a photo and the woodblock print of that same photo, and ask it to match the print.

This training set does not work that way. It is the public ukiyoe2photo collection: one folder of woodblock prints, and another folder of landscape photographs. A print in the first folder is not the woodblock version of a photograph in the second. They are two separate piles of pictures.

Training can therefore ask for two things only. The output should look as if it belongs in the print pile. And the place in the photograph should still be recognizable after the translation. There is no third image that says what the correct print of that exact scene would be.

Translate both ways, so the scene has a way home

The model learns the translation in both directions at the same time.

One network turns photographs into prints. Another turns prints back into photographs. Take a photo, make a print, then turn that print back into a photo. You should get the photo you started with. Take a print, make a photo, then turn that photo back into a print. You should get the print you started with.

That round trip is the stand-in for a paired answer. If the bridge, the hill, or the boat disappeared on the way out, the way back would fail. Each direction is what keeps the other one honest about content.

Style is still a GAN problem, played once for each pile. A critic of prints tries to tell real prints from generated ones. A critic of photographs does the same for photos. The translators try to make those critics accept what they made.

The four networks

After the naming swap described in the next section, the four networks are these.

  • The photo-to-print network is G_A. It has about 11.378 million parameters. The website uses this network and no other.
  • The print-to-photo network is G_B. It is the same size. It exists so the round trip can be checked, and so the model also learns the reverse translation while training.
  • The print critic is D_A. It has about 2.765 million parameters. It looks at real prints and at the prints G_A just made.
  • The photo critic is D_B. It is the same size. It looks at real photographs and at the photographs G_B just made.

Why the letters in the notebook feel backwards

In the dataset, domain A is the prints and domain B is the photographs. The training option is called BtoA, which means translate B into A: photographs into prints.

Before each loss is computed, the code swaps the two loaded batches. Inside that loss, the photograph is stored under the name real_A, and the print is stored under the name real_B. G_A reads real_A and writes a print. So the letter A on the dataset means prints, while the letter A on real_A in the saved pictures means the photo being translated.

Read the saved test grid with that swap in mind:

  • real_A is the photograph.
  • fake_B is the print made by G_A.
  • rec_A is that print sent back through G_B, the reconstructed photograph.
  • real_B is a real print from the other folder.
  • fake_A is the photograph made from that print by G_B.
  • rec_B is that photograph sent back through G_A, the reconstructed print.

What one training step does

Each step draws one photograph and one print, independently. They are not a pair. The batch size is 1, so a line in the log is the story of a single image, not an average over the epoch.

  1. The photograph goes through G_A, which tries to make a print. That print goes through G_B, which tries to recover the photograph. The difference between the recovery and the original photograph is cycle_A.
  2. The print goes through G_B, which tries to make a photograph. That photograph goes through G_A, which tries to recover the print. The difference from the original print is cycle_B.
  3. G_A is also handed a real print and asked to give that print back unchanged. G_B is handed a real photograph and asked to give that photograph back unchanged. These are idt_A and idt_B. They stop a translator from recoloring an image that is already in the style it is supposed to produce.
  4. D_A tries to accept real prints and reject generated prints. D_B does the same for photographs. The translators are trained to make the critics accept their fakes. For that step the critics are frozen, then the critics are trained while the translators are held still.
  5. The critic is not always shown the fake from this exact step. A replay buffer keeps 50 recent fakes. Sometimes an older one is substituted, so the critic does not forget mistakes the translator has already moved on from.

How hard each pressure pulls

The critic uses least-squares loss. A real image is asked to score 1, a fake is asked to score 0, and the penalty is the squared distance from that target. When the critic is already very sure, this still gives the translator a usable push.

The round trip and the identity check use L1: the average absolute difference between pixel values. Pixel values inside the network run from -1 to 1.

The round-trip error is multiplied by 10 before it is added in. That 10 is the cycle weight. The identity error uses half of that weight, so it is multiplied by 5. The chart and the log already include those multipliers. A plotted cycle value near 1 means the underlying average absolute error is about 0.1 on that -1 to 1 scale.

A small round-trip error means the two translators preserved the picture well enough to come home. Looking like a woodblock is the critics' job. The test pictures at the end of the notebook are where you judge that by eye.

What the networks are made of

Both translators are a ResNet with nine residual blocks, the usual CycleGAN generator. The image is padded by mirroring its own edges, so the border is a reflection of the picture. A first convolution reads a wide neighborhood of each pixel. Two stride-2 layers shrink the map to a quarter of the width and height. Nine residual blocks then change that map, and each block can also pass its input through, which lets a deep stack edit the picture without rebuilding the layout from nothing. Two transposed convolutions restore the full size. The last layer is tanh, so every output sits between -1 and 1.

Both critics are 70×70 PatchGANs with three layers. They score overlapping patches about 70 pixels across, rather than giving one score for the whole frame. The translator is pushed on local texture: the line, the flat color, the grain.

Inside the translator, normalization is instance norm. Each image is centered and scaled using its own statistics, with no learned scale or shift on top of that. Dropout is off. Weights start from a normal distribution with standard deviation 0.02. Those are the CycleGAN defaults this run kept.

The schedule that was actually run

The CycleGAN paper often trains for 200 epochs. This run uses 20.

One epoch is one pass over the larger folder, 6,287 images. The smaller folder is sampled so that every step still has one image from each side.

What is left once training is over

Inference uses G_A only. G_B and both critics stay inside the checkpoint because that is how the training code saves the whole model, and the page does not load them. The browser copy of G_A is on the tab.

Open src/notebooks/trained_fin.ipynb. Two pictures matter. The loss chart is the figure drawn after the training cell. The eight test rows are the last figure in the notebook. This file is the finished run. A single printed log line is one image at one step, so use the chart when you want the history and the test figure when you want to talk about picture quality.

The notebook's own training output starts again at epoch 17 and ends at epoch 20. The chart still contains all 20 epochs. The checkpoint restores the earlier loss history, and the plot is drawn from that full history.

Nothing else was measured. There is no FID, LPIPS, SSIM, or classification accuracy. The evidence is the eight curves, plus those eight test photographs.

What one printed line is

Every 100 training steps, the cell prints the latest five log lines. The next print overlaps that window, so reading the printed text as a sequence will count the same steps more than once. The chart is the clean history.

Because the batch size is 1, a line is one photograph and one print. A spike is one difficult image. It is not an epoch average.

The names are the ones left after the BtoA swap, explained on the tab. In short:

  • D_A is the print critic. G_A is the photo-to-print network trying to fool that critic.
  • D_B is the photo critic. G_B is the print-to-photo network trying to fool that critic.
  • cycle_A is photo, then print, then back to photo. The number already includes the weight of 10.
  • cycle_B is print, then photo, then back to print. The number already includes the weight of 10.
  • idt_A is G_A asked to leave a real print unchanged. The number already includes the weight of 5.
  • idt_B is G_B asked to leave a real photograph unchanged. The number already includes the weight of 5.

The last logged step is epoch 20, iteration 125,700: D_A 0.037, G_A 0.695, cycle_A 0.822, idt_A 0.356, D_B 0.105, G_B 0.534, cycle_B 0.570, idt_B 0.258.

Treat that line as an example of one step near the end. Describe the shape of the chart when you describe the run.

How the chart is laid out

Each panel is one of those eight numbers, drawn for the whole run.

The horizontal axis is a log step, not an epoch. One point is written every 100 training iterations. An epoch of 6,287 images is about 63 points. Twenty epochs are about 1,257 points, which is why the axis runs to roughly 1,250. The left half of the axis is the ten epochs at learning rate 0.0002. The right half is the ten epochs in which that rate falls to zero.

The vertical scales are separate. A cycle value near 1 and a critic value near 0.2 are different kinds of number. The cycle and identity panels already include their weights, so they sit on a larger scale than the raw pixel error.

The four jagged curves

D_A, G_A, D_B, and G_B stay jagged for the whole run.

D_A and D_B sit mostly between about 0.05 and 0.3, with spikes above 0.5. G_A and G_B sit mostly between about 0.2 and 1.0, with spikes near 1.75. None of them trends down toward zero.

For a least-squares GAN, that shape is a balance. The critic keeps catching some fakes, and the translator keeps getting others accepted. If the critic's curve fell to zero and stayed there, the critic would have given up. If the translator's curve fell to zero and stayed there, the critic would no longer be providing a useful target. The noise is one image at a time: a hard photograph makes a spike, and the next photograph does not.

The four curves that fall, then level off

cycle_A, cycle_B, idt_A, and idt_B are the content curves.

cycle_A starts near 8 and cycle_B near 4.5. Both fall within the first few epochs, about the first 200 points on the chart, and then sit in a noisy band around 1. On the network's -1 to 1 pixel scale, a plotted value near 1 means the average absolute error of the round trip is about 0.1, because the plot includes the factor of 10.

idt_A starts near 2 and idt_B near 2.5. They fall on the same early schedule and then stay mostly below 1. idt_B has one sharp spike near 4 later in training, one photograph that the print-to-photo network failed to leave alone.

The early drop means the round trip started keeping the input. The later flat band means that part of training had settled. The line stays noisy at the end because each point is still one image.

The eight test rows

The last figure shows eight photographs the training loop did not use for those steps. Each row has three pictures:

  1. The photograph, labeled real_A in the code.
  2. The print G_A made from it, labeled fake_B.
  3. The photograph reconstructed by sending that print through G_B, labeled rec_A.

Look at the third column first. The scenes mostly survive: the layout you see on the left is still there on the right. That matches the cycle curves settling near 1.

Then look at the middle column, which is the actual product. It is uneven. Some rows, such as the canal and the duck, read as painted. Others look closer to the original photograph with a grain and a palette laid over it. The last landscape loses the hills. That spread is the quality this 20-epoch checkpoint reached.

The figure is eight examples. It is not a score over the whole test set, and the run did not compute one.

If you are explaining the figure

  • The prints and the photographs were never pairs. The round trip is what kept the scene, and the print critic is what pushed the look.
  • The jagged critic and translator curves are the healthy ones. The cycle and identity curves are the ones that should fall and then sit still.
  • A cycle value on the chart is already multiplied by 10. Near 1 means a small pixel error on the way home, on the -1 to 1 scale the network uses.
  • The middle picture in each test row is the thing the project is for. Some of them look like prints. Some of them mostly restyle the photograph. The reconstructed photo can look faithful either way.
  • After epoch 20 the learning rate is zero, and latest.pt is the finished checkpoint.

Train

Training stays off this machine. The notebook that trains is src/notebooks/ukiyoe_cyclegan.ipynb. Upload that file to Colab, choose a T4 GPU runtime, and run the cells from the top.

The schedule is 20 epochs. For the first 10, the learning rate stays at 0.0002. For the next 10, it falls in a straight line to zero. One free Colab session will not finish that. If the session drops, start a new one and run the cells from the top again. The notebook looks for MyDrive/ukiyoe-cyclegan/checkpoints/ukiyoe2photo/latest.pt and continues from whatever that file contains. A file saved at the end of an epoch resumes at the next epoch. A file saved partway through an epoch resumes the rest of that epoch.

The finished run is already stored. src/notebooks/trained_fin.ipynb shows epoch 20 ending with the learning rate at 0. Running the training notebook again on that checkpoint does not train further, because a learning rate of zero takes steps of size zero.

During training, every 100 steps the cell prints the last five stat lines and overwrites checkpoints/ukiyoe2photo/loss_plot.png with the chart of the whole history. How to read that chart is the tab.

Translate a photo on this machine

The page people use does not load PyTorch, and it does not load the training checkpoint. It runs one network, the photo-to-print translator G_A, inside the browser.

That network is stored as src/client/public/g_a.onnx, about 45 MB. ONNX here is a frozen copy of G_A that the browser's runtime can execute. The full training checkpoint, about 340 MB, stays at src/server/ukiyoe_cyclegan.pt. That file holds all four networks and the loss history. It is not committed. If you replace the checkpoint and want the page to match it, export G_A again from the repository root:

PYTHONPATH=src uv run python src/server/export_onnx.py

To build and open the page locally, from the repository root:

./start

The script installs the Python and npm dependencies, builds the page, and serves it at http://127.0.0.1:8000.

On the page, choose one photo. The browser stretches it to 256×256, because that is the size G_A was trained to see. A wide photo is squashed to a square as part of that stretch. The page then shows that 256×256 picture beside the print. The first translation also downloads the model file, about 45 MB. Later translations reuse it.

The hosted copy of the same page is the tab.

The same page you can run locally is already hosted at ukiyoe-gan-ni3ravs-projects.vercel.app. Someone who opens that address downloads the photo-to-print network and runs it in their own browser. The server is only serving files. It does not translate the photograph.

The Vercel project is ukiyoe-gan, on the team ni3ravs-projects. Production follows the master branch of github.com/ni3rav/style-transfer-gan. A push to that branch builds the page and publishes it.
